02

How I work

The same five steps on every build, from a single flow to a full solution.

  1. 01

    Map the process

    I sit with the people who run it and write every step down, workarounds included, before I build anything.

    In practice The failure modes of the current process go on paper first, so the build fixes real defects.

  2. 02

    Build it to fail loudly

    Every flow alerts when it breaks. A system that stops quietly counts as broken.

    In practice The Dataverse build ends with a script that reads 30 facts back from the live environment.

  3. 03

    Test before go-live

    Real cases, edge cases and the input that must be rejected all run before anyone depends on the system.

    In practice 17 cases and 300 combinations on a lease application engine. 121 tests gate ApplyForge in CI.

  4. 04

    Write the runbook

    Triggers, schedule, alerts and recovery steps, written down so the next person can run it without me.

    In practice Five inherited flows got failure alerting and a runbook in my first month.

  5. 05

    Measure the result

    Before and after from real runs. Estimates stay labelled until they are measured.

    In practice A system that is built but not live gets no value claimed on this page.
